# Email provider connections

The app offers ten service presets plus Other IMAP/SMTP. These are coverage choices, not a market-share ranking. Settings below were checked against official documentation on 2026-09-10; this is not a claim of successful live authentication or sending with every provider. Account policy, subscription, administrator consent, and OAuth registration still determine access.

All preset incoming connections use IMAP port 993 with implicit TLS. SMTP port 587 uses mandatory STARTTLS; port 465 uses implicit TLS. Server settings remain editable for custom domains and regional accounts. Provider IDs in the Python engine describe transport implementations (`gmail`, `graph`, `yahoo`, `imap`), not the number of supported email services.

Discovery recognizes listed public domains and existing aliases. Google Workspace and Microsoft 365 custom domains may be inferred from MX records. Other custom domains use SRV records where available, then unverified `imap.<domain>` / `smtp.<domain>` guesses. MX and guessed settings are suggestions, not successful connection checks; use the provider's actual account settings when they differ. Selecting a provider preset allows a custom-domain account to use that provider's settings without relying on domain inference.

## Native OAuth registration

Use authorization code with PKCE S256, a fresh random state, the system authentication browser, and an exact registered callback. Native clients are public clients: do not ship a client secret in the iOS bundle. Google recommends its iOS Sign-In SDK and an iOS OAuth client registration with the app's actual bundle ID. Microsoft registration must permit the intended personal and/or organizational account types. [Google native OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [Google client policy](https://developers.google.com/identity/protocols/oauth2/policies), [Microsoft PKCE flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow).

Google IMAP/SMTP uses SASL XOAUTH2 with the scope `https://mail.google.com/`. The authorization endpoint is `https://accounts.google.com/o/oauth2/v2/auth`; token endpoint is `https://oauth2.googleapis.com/token`. Public production apps normally require restricted-scope verification; testing/personal-use exceptions exist. A backend able to access restricted Gmail data can also require annual security assessment. Plan beta access around the registered project's test-user or verification state. [Gmail OAuth](https://developers.google.com/workspace/gmail/imap/xoauth2-protocol), [restricted-scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification).

Microsoft IMAP/SMTP uses SASL XOAUTH2 with delegated scopes `https://outlook.office.com/IMAP.AccessAsUser.All`, `https://outlook.office.com/SMTP.Send`, and `offline_access`. The endpoints are `https://login.microsoftonline.com/{tenant}/oauth2/v2.0/authorize` and `https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token`. The `common` tenant supports the app registration's permitted account types. These are Exchange protocol tokens, not Microsoft Graph tokens; Graph access requires its own resource scopes/token. The engine's historical `graph` provider ID does not change that distinction. [Microsoft protocol OAuth](https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth).

## Other accounts and limits

Other IMAP/SMTP accepts provider-supplied hostnames, ports, usernames, and credentials. Server addresses alone cannot establish compatibility: the service must allow the protocol, authentication method, and account's plan. Use TLS with certificate validation; do not send credentials before a STARTTLS upgrade completes. Test connection and mailbox access before relying on the account, then perform an explicitly authorized send/receive check to validate outgoing delivery.

Proton is not a direct iOS IMAP preset. Proton Bridge requires a paid plan and runs on macOS, Windows, and Linux, explicitly not mobile devices. Its business SMTP submission feature supplies outgoing mail, not full mailbox access. Tuta does not offer IMAP/POP3/SMTP access. [Proton Bridge](https://proton.me/support/imap-smtp-and-pop3-setup), [Tuta support](https://tuta.com/de/support/howto).
